O comportamento do bot baseia-se numa máquina de estados sequencial, com inteligência para lidar com desvios de comportamento, áudios e abandonos.

	Mecanismos Avançados de Resiliência
1. Ingestão de Áudio via Whisper
Sempre que a propriedade messageType do webhook for igual a audioMessage, o middleware intercepta o arquivo .ogg, faz o streaming do binário para a API do Whisper e injeta a string de texto transcrita de volta na variável de entrada do bot-engine. A partir desse ponto, o bot processa a informação como se tivesse sido digitada pelo aluno.
2. Tratamento do Estado de FALLBACK
Se o aluno enviar um texto livre ou um comando inválido durante os estados de coleta (COLLECTING_REPS ou COLLECTING_WEIGHT), o motor de estados:
1. Altera temporariamente o estado para FALLBACK.
2. Envia o input do aluno para a camada da LLM com um prompt contextualizado (Ex: "O aluno está no meio do treino de Supisno e disse '[TEXTO]'. Responda de forma curta, motivadora e peça educadamente para ele confirmar o dado numérico solicitado anteriormente").
3. Após o envio da resposta gerada pela IA, o sistema reverte o estado do aluno na tabela bot_state para o estado de coleta original, garantindo que o fluxo não quebre.
3. Expiração de Sessões Abandonadas (Cron Job)
Para evitar que treinos fiquem "presos" indefinidamente se o aluno for embora da academia sem encerrar a sessão, um job interno (cron/session-cleanup.ts) é executado a cada 30 minutos via Fastify ou Supabase Edge Functions.

Plano de Endpoints (Gestão do Personal Trainer)

5. Monitorização (Dashboards)
